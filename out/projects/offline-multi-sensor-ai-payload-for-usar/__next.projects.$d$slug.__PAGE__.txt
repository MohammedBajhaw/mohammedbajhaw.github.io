3:Tfce,<h2>Mission context</h2><p>Urban search-and-rescue operations can disrupt power, cellular coverage, and network infrastructure at exactly the moment autonomous robots must continue to sense, navigate, and communicate. This project develops a modular edge-AI payload that keeps the full victim-detection and voice-interaction workflow on the robot rather than depending on cloud services.</p><figure><img src="https://engportfolio-zhkmdjuy.manus.space/manus-storage/figure-002_42d4fde2.jpg" alt="Physical multi-sensor payload mounted on the TurtleBot rescue platform" /><figcaption>Physical multi-sensor payload used for the mobile rescue-platform validation.</figcaption></figure><h2>Integrated system</h2><p>The system was validated primarily on a TurtleBot3 Waffle Pi and uses an NVIDIA Jetson TX2 as its edge-compute unit, with an STM32F411 acting as a dedicated sensor hub. The architecture integrates ROS 2 navigation with multiple sensing modalities and a local communication stack.</p><ul><li><strong>Visual perception:</strong> a TensorRT FP16-optimised YOLOv11n detector supports person detection in the on-board camera stream.</li><li><strong>Presence confirmation:</strong> FMCW bio-radar and thermal sensing provide redundant cues when conventional visual detection is uncertain.</li><li><strong>Offline dialogue:</strong> the voice pipeline links Faster-Whisper speech recognition, Gemma 3 language inference, and Piper text-to-speech without internet access.</li><li><strong>Long-range telemetry:</strong> hybrid Wi-Fi and LoRa SX1278 communication carries mission data across challenging operating conditions.</li></ul><h2>Resource-aware autonomy</h2><h3>Wake-on-Suspect operation</h3><p>A thermal-triggered protocol keeps the high-power detection pipeline inactive until a suspect heat signature requires confirmation. This reduces unnecessary GPU use while retaining a responsive investigation path.</p><h3>SIGKILL-based state management</h3><p>To run large models on a memory-constrained Jetson TX2, the Master State Machine explicitly retires the outgoing model process before loading the next task. This approach avoids overlap in model memory demand and makes mission-mode transitions deterministic.</p><figure><img src="https://engportfolio-zhkmdjuy.manus.space/manus-storage/figure-006_f8a34a23.jpg" alt="Rescue Robot Command interface and RViz navigation display" /><figcaption>Integrated Rescue Robot Command interface with RViz navigation and sensor-status monitoring.</figcaption></figure><h2>Measured validation</h2><ul><li><strong>YOLOv11n:</strong> 96.1% mAP@50 at 26.3 FPS with TensorRT FP16, a 7.5× inference-speed improvement over the reported baseline.</li><li><strong>FMCW bio-radar:</strong> approximately 94% human-presence detection in controlled laboratory conditions.</li><li><strong>Voice interaction:</strong> the complete local speech-to-speech pipeline measured approximately 17 seconds end-to-end on the Jetson TX2; this is a current optimisation target rather than a cloud-dependent fallback.</li><li><strong>Memory resilience:</strong> 0% out-of-memory crash rate with a 71% reduction in mode-switching latency.</li><li><strong>Operational efficiency:</strong> the Wake-on-Suspect protocol extended operational runtime by 35% compared with continuous always-on inference.</li><li><strong>Telemetry reach:</strong> reliable delivery was measured up to 600 m through reinforced concrete indoors and 2.5 km line-of-sight outdoors.</li></ul><blockquote>The platform is designed as a hardware-agnostic controller that can be adapted to ROS 2-compatible mobile bases after the primary TurtleBot validation.</blockquote><h2>Engineering contribution</h2><p>The project brings perception, edge computing, safety-oriented resource management, navigation support, and human-robot dialogue into a single deployable rescue-robot payload. Its central contribution is not a single model: it is the orchestrated, offline operation of complementary sensing and AI subsystems under embedded hardware constraints.</p>6:X
